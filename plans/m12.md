Status: **implemented** (M12 shipped; plan kept for the record). Built from the
task spec hand-off, audited against the current repo (M1–M11 already shipped).

---

## What this milestone adds (new delta only)

The package already ships proxy-only adapters (`resend`/`postmark`/`sendgrid`)
that POST `{ provider, formId, to, payload }` to a consumer `/api/contact`
endpoint. M12 extends the *generic* `custom`/`json` transport with the same
envelope via an explicit dispatch **`target`**, so a single generic route can
fan out to **any** backend (CF7, Mailchimp, Mailgun, Fluent Forms, …) while the
provider's URL and master keys stay server-side in `.env` — nothing
provider-shaped is ever visible to the browser.

### Decisions locked in (user)

1. **Wire envelope stays the legacy shape** `{ provider, formId, to, payload }`
   — one documented wire format; `provider` is the dispatch key. The legacy
   proxy-only flow is untouched.
2. **Schema key is `target`, not `mailer`/`to`** — `to` is already the
   client-safe recipient hint; `mailer` is the outer spec key. `target`
   names the server-side backend.
3. **`MailTarget` is the full provider surface, open-ended**: every
   `MailerProvider` (any direct adapter can be proxied the same way) + backend
   -only targets (`mailchimp`, `mailgun`, `fluentforms`, `ninjaforms`,
   `smtp`, `webhook`, …) + `(string & {})` so a private/self-hosted backend
   never needs a package release.
4. **Additive only**: absent `target`, the `custom`/`json` transport posts the
   plain canonical payload exactly as before (no consumer breakage).
5. Server route is consumer-side (raw-`fetch` docs, zero deps), per the
   zero-runtime-dependency rule and the existing `docs/transport-proxies.md`
   pattern.

## Changes

### Schema — `src/core.ts` (+ `src/mailers/index.ts` type twin)

- `export type MailTarget = MailerProvider-union | "mailchimp" | "mailgun" |
  "mailjet" | "mandrill" | "sparkpost" | "ses" | "smtp" | "mailerlite" |
  "brevo" | "convertkit" | "customerio" | "klaviyo" | "fluentforms" |
  "ninjaforms" | "gravityforms" | "forminator" | "elementor" | "webhook" |
  (string & {})`.
- `MailerConfig.target?: MailTarget` — JSDoc'd as the server-side dispatch
  identifier (client-safe, no URLs/keys).
- Spec block shape:
  ```jsonc
  "mailer": {
    "provider": "custom",
    "endpoint": "/api/contact",   // optional — defaults to /api/contact with a target
    "formId": "z10",
    "target": "cf7"
  }
  ```

### Transport — `src/mailers/json.ts`

- When `config.target` is set: POST `{ provider: config.target, formId, to,
  payload: canonicalObject(...) }` as JSON to `config.endpoint ?? "/api/contact"`
  (2xx = success; `message`/`error` surfaced on failure — shared with the
  existing path).
- Untagged: unchanged FormData path (`canonicalData`).

### Shell + engine

- `src/runtime/markup.ts`: `data-mailer-target` serialised from
  `mailerSpec.target`; `warnMissingConfig` stops requiring an endpoint for
  `custom`/`json` when a target is present.
- `src/runtime/engine.ts`: config build gains
  `target: configOverride?.target ?? form.dataset.mailerTarget`; option docs
  list `target` among the mailer-config extras.
- `src/runtime/index.ts`: `MailTarget` re-exported (type only).

### Docs

- `README.md`: generic-transport section documents the `target` key + proxy
  envelope; transport-proxies intro points at the generic dispatcher.
- `docs/transport-proxies.md`: rewritten as **Generic multi-provider dispatch**
  — envelope, client config, `.env` sample, validation (400 on missing
  `provider`/`formId`), optional `ALLOWED_FORM_IDS` guardrail (403), normalized
  `{ success: true }` / `{ error }`, Next.js App Router + Astro routes with
  `cf7` / `resend` / `postmark` / `sendgrid` / `mailchimp` cases, env table,
  SMTP/Nodemailer note.
